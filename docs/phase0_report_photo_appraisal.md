## 1. 画像・動画の受信

**確認できたこと**
- 画像は `code.gs:284` で `v2HandleImage_` に渡る。実装は `v2-flows.gs:356-371`。
- **中身は取得も保存もしていない。枚数を数えているだけ**（`s.data.photos` を +1）。`getMessageContent` はどのファイルにも無い。
  Drive への保存があるのは `kaitori-ledger.gs:102-109` だけで、これは買取台帳用の別系統。
  → いまはオーナーが LINE のトークで直接写真を見る運用。
- **`imageSet` は未対応**（語がコードに存在しない）。同時送信は1枚ずつ別イベントで届き、枚数だけ増える。
- 返事は `s.data.photos === 1` のときだけ返している。結果として**「最初の1枚にだけ返事、2枚目以降は無言」**＝要件が求める「まとめて1回だけ返す」に近い挙動が、すでに実現できている。
- **動画の受信処理は無い**（`message.type === 'video'` の分岐が存在しない）。送信側だけ `v2-flows.gs:104` で診断動画を video メッセージとして送っている。

**影響**
- 要件2.3 のまとまり6（診断動画）・7（充電器は写真か動画）で**動画を受け取るには新規実装が要る**。
- 要件2.8 の「まとまりごとの受信数」を記録するには、いまの単純な通し枚数カウントを、まとまり別のカウンタに作り替える必要がある。
- 写真の実体を保存するかは要件に明記が無い。**現状どおり保存しない（オーナーがトークで見る）でよいか、確認が要る。**

**未確認**
- 本番 GAS のスクリプトプロパティの中身、Drive のフォルダ構成（買取台帳用フォルダID）。

## 2. 返信方式

**確認できたこと**
- **reply が主**。`reply(event.replyToken, [...])` と `v2Reply_` が全フローの基本。複数メッセージは配列で1回の reply に載せている。
- **push はオーナー通知で実績あり**（`pushMessage_(OWNER_LINE_USER_ID, ...)`、`code.gs:1536`）。

**影響**
- 要件10 の「`total` が分かるときは最後の1枚の replyToken で返す」はそのまま乗る。
- ただし上記1のとおり、**いまの「最初の1枚だけ返す」方式でも要件は満たせる**。遅延トリガーで push する案は不要の可能性が高い（push の無料枠も使わずに済む）。

**未確認**
- 当月の push 無料枠の残量。

## 3. セッション状態

**確認できたこと**
- **CacheService（6時間）が主、Sheets の `sessions` タブがバックアップ**（`v2-core.gs:82-121`）。
  `V2_SESSION_TTL_SEC = 6 * 3600`、列は `userId / flow / step / intent / data / updated_at`。
- **Sheets から復元するときも6時間で切っている**（`v2-core.gs:104`：更新から6時間を超えていたら `null` を返す）。
- 状態判定はできている。`v2HandleImage_` は `s.step` を見て写真工程かどうかを判定しており、
  要件2.3 の「写真ステップ以外で届いた画像はフローを進めない」は**すでに満たしている**。

**影響（重要）**
- **「あとで続きから送れます」と約束するなら、写真セッションの保持期間を延ばす必要がある。**
  いまのままでは、6時間を超えた再開は必ず最初からになる（変更案 D-2 の指摘どおり）。
- 写真工程以外で画像が来たときの案内が**毎回**返る。要件は「1回だけ」なので、ここは直す。

**確認できたこと**
- `notifyOwner_(channel, from, subject, content)`（`code.gs:1522-1536`）が `OWNER_LINE_USER_ID` へ push する。

**影響**

## 実装の見通し（良い材料）

- まとめ返信は**すでに近い挙動が実装済み**（最初の1枚だけ返す）。push 枠を使う遅延処理は要らない見込み。
- 写真工程かどうかの**状態判定は実装済み**。旧ボットの「状態に関係なく反応する」不具合は再発しない作りになっている。
- **動画の配信と video メッセージは実績あり**。新規に必要なのは「動画を**受け取る**側」だけ。
- 集計を壊さない境界（`ROUTE_IDS` と `lineRoutes.js` の `msg` 末尾）がはっきりしている。
